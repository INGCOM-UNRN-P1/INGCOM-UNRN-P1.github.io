(0x6010h)=
# 0x6010h: Validá los datos en la frontera del programa

:::{admonition} Categoría: Disciplina de Construcción Sistemática (0x60XX) — Propuesta
:class: note
Código de regla: `0x6010h` | Soporta corrección automática: **No**
:::

:::{seealso} Reglas relacionadas
* {ref}`0x300Ch` — verificar límites antes de acceder a un arreglo.
* {ref}`0x4002h` — validar retornos de lectura.
* {ref}`0x6008h` — contrato de la función.
:::

## Enunciado normativo

> Todo dato que ingresa desde fuera del programa (teclado, archivo,
> argumentos de línea de comandos, red) **DEBE** validarse inmediatamente en
> la frontera, antes de usarse. **NO DEBE** confiarse en que la entrada es
> correcta "porque el usuario debería ingresar bien".

## ¿Por qué existe esta regla?

### El problema

El exterior del programa es hostil e impredecible. Un usuario puede escribir
letras donde se espera un número, un archivo puede venir truncado y un
argumento puede faltar. Si el dato se usa sin validar, el error se propaga
profundamente y se manifiesta lejos de su origen, donde es caro de rastrear.

Validar en la frontera concentra todas las suposiciones en un único lugar y
garantiza que el interior del programa trabaje sólo con datos confiables.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Comportamiento indefinido | Usar un entero sin inicializar porque `scanf` falló. |
| Desbordamiento | Copiar entrada de longitud ilimitada en un buffer fijo. |
| Crash | Acceder a un arreglo con un índice ingresado por el usuario. |
| Bug silencioso | Un valor basura se propaga y produce resultados absurdos. |

### Fundamento en la cátedra

Es un principio de robustez estándar: los datos no confiables se sanean en el
punto de entrada. Se articula con {ref}`0x300Ch` (límites), {ref}`0x4002h`
(retornos de lectura) y {ref}`0x6006h` (contrato de funciones).

## Alcance y excepciones

Aplica a todo canal externo: `scanf`, `fgets`, `fread`, `argv`, variables de
entorno, sockets, archivos. No se revalida dentro del programa lo ya
validado en la frontera (se documenta el contrato, eso es suficiente). Una
constante literal del propio código no es entrada externa.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Confiar en `scanf`

```c
int edad;
printf("Edad: ");
scanf("%d", &edad);

char categoria = (edad >= 18) ? 'A' : 'B';
```

Por qué falla: si el usuario escribe "abc", `scanf` falla, `edad` queda
indeterminada y la comparación usa basura. Además el ternario está prohibido
({ref}`0x1007h`).

### ❌ Contraejemplo 2 — Copiar entrada sin límite

```c
char nombre[32];
printf("Nombre: ");
scanf("%s", nombre);
```

Por qué falla: una entrada de 100 caracteres desborda `nombre` y corrompe la
pila; es un *buffer overflow* clásico. Debe usarse un ancho máximo
({ref}`0x400Ah`, {ref}`0x5006h`).

### ✅ Ejemplo conforme 1 — Validación con retorno

```c
int edad;
printf("Edad: ");

if (scanf("%d", &edad) != 1) {
    fprintf(stderr, "Entrada invalida\n");
    return EXIT_FAILURE;
}

if (edad < 0 || edad > EDAD_MAXIMA) {
    fprintf(stderr, "Edad fuera de rango\n");
    return EXIT_FAILURE;
}
```

Se verifica el retorno de `scanf` y el rango antes de usar `edad`.

### ✅ Ejemplo conforme 2 — Lectura acotada con `fgets`

```c
char nombre[32];
if (fgets(nombre, sizeof(nombre), stdin) == NULL) {
    fprintf(stderr, "Error de lectura\n");
    return EXIT_FAILURE;
}

nombre[strcspn(nombre, "\n")] = '\0';
```

`fgets` nunca escribe más de `sizeof(nombre) - 1` bytes y se verifica el
retorno.

### ⚠️ Casos límite

- **`argv`:** verificar que `argc` alcanza antes de tocar `argv[i]`.
- **Archivos:** un archivo "propio" puede venir editado o corrupto; validar
  formato y cantidades.
- **Valores límite:** comprobar también `INT_MAX`, cadenas vacías y
  cantidades negativas, no sólo el tipo.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `kaneda` | auditoría de seguridad | `scanf` sin ancho, `gets`, copias sin límite. |
| `valgrind` | `valgrind ./programa` | Lecturas de memoria no inicializada por entrada fallida. |

## Checklist de autocontrol

- [ ] ¿Verifiqué el retorno de toda lectura?
- [ ] ¿Comprobé el rango del valor ingresado?
- [ ] ¿El buffer de destino acota la escritura?
- [ ] ¿`argv` se valida antes de usarse?
