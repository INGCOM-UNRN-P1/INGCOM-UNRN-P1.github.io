# Antipatrón AP-0x1010h: Precedencia errónea entre asignación y comparación

:::{admonition} Regla de Estilo Asociada: 0x1010h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la **[0x1010h: Delimitación obligatoria con bloque de llaves en lazos do-while](0x1010h.md)**.
:::

```{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1010h` | Categoría: Estructuras de Control y Lazos (0x10XX)
```


## Diagnóstico
El operador de comparación '==' tiene mayor precedencia que '='. La variable 'p' recibirá el resultado booleano (0 o 1) en lugar del retorno de la función.

## Justificación Pedagógica y de Estándar C
El código de diagnóstico `0x1010h` identifica una práctica desaconsejada en la arquitectura pedagógica de la materia.
Esta transgresión incrementa el acoplamiento, produce comportamiento indefinido o vulnera los invariantes de memoria.

## Sugerencia de Corrección
Encerrá la asignación entre paréntesis: 'if ((p = fn()) == NULL)'.

## Ejemplos

### Código con Antipatrón (Incorrecto)
```c
if (p = malloc(10) == NULL) { ... }
```

### Código Idiomático Refactorizado (Correcto)
```c
if ((p = malloc(10)) == NULL) { ... }
```
