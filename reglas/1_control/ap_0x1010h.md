(ap_0x1010h)=
# Antipatrón AP-0x1010h: Precedencia errónea entre asignación y comparación

:::{admonition} Regla de Estilo Asociada: 0x1010h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la
**[0x1010h: Delimitación obligatoria con bloque de llaves en lazos do-while](0x1010h.md)**.
:::

:::{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1010h` | Categoría: Estructuras de Control y Lazos (0x10XX)
:::

## Síntoma en el código del estudiante

En una misma expresión aparecen `=` y `==` sin paréntesis que separen la
asignación de la comparación:

```c
if (p = malloc(10) == NULL)
{
    reportar_error();
}
```

## Diagnóstico

### Mecanismo del defecto

La precedencia de `==` es mayor que la de `=` (ISO/IEC 9899:2011 §6.5.16 y
§6.5.9). Por lo tanto la expresión se agrupa como `p = (malloc(10) == NULL)`:
primero se evalúa la comparación del puntero contra `NULL` (resultado booleano)
y ese 0 o 1 **se asigna a `p`**. El puntero devuelto por `malloc` nunca queda
guardado.

### Consecuencia observable

`p` recibe `0` o `1` en lugar de una dirección válida; usarlo después produce un
acceso a memoria inválido o un `free` incorrecto. Si `malloc` falló, la
comparación es verdadera y `p` queda en `1`, un puntero no nulo e inutilizable.
Es comportamiento indefinido al desreferenciar.

## Fundamento en el estándar C11

ISO/IEC 9899:2011 §6.5.16 (asignación simple) y §6.5.9 (`==`) fijan la
precedencia que causa el agrupamiento. La cátedra prohíbe las asignaciones
embebidas en condiciones (`0x1014h`) y exige separar la operación. El resultado
correcto requiere paréntesis: `(p = malloc(10)) == NULL`.

## Corrección idiomática

### ❌ Código con el antipatrón

```c
if (p = malloc(10) == NULL)
{
    reportar_error();
}
```

### ✅ Código refactorizado

```c
p = malloc(10);
if (p == NULL)
{
    reportar_error();
}
```

La asignación se separa de la comparación; no hay ambigüedad de precedencia y el
valor de `p` es el que devolvió `malloc`. Si se necesitara mantener el patrón en
una línea, el paréntesis obligatorio sería `if ((p = malloc(10)) == NULL)`.

## Errores típicos al compilar o ejecutar

```text

```

## Checklist de verificación

- [ ] ¿Alguna condición combina `=` y `==` sin paréntesis?
- [ ] ¿La asignación quedó guardada en la variable correcta?
- [ ] ¿Separé la operación de la comparación?
- [ ] ¿Verifiqué que `malloc` no devolvió `NULL` antes de usar `p`?
