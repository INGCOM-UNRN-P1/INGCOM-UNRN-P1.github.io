# Antipatrón AP-0x1019h: Uso de salto goto hacia atrás vulnerando programación estructurada

:::{admonition} Regla de Estilo Asociada: 0x1006h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la
**[0x1006h: No utilizar la instrucción goto](0x1006h.md)**.
:::

:::{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1019h` | Categoría: Estructuras de Control y Lazos (0x10XX)
:::

## Síntoma en el código del estudiante

Un `goto` salta hacia atrás a una etiqueta anterior para repetir un bloque,
simulando un lazo:

```c
repetir:
    /* ... */
    goto repetir;
```

## Diagnóstico

### Mecanismo del defecto

`goto` transfiere el control a la etiqueta sin pasar por ninguna estructura
(ISO/IEC 9899:2011 §6.8.6.1). Un salto hacia atrás reconstruye a mano un lazo:
la condición de corte queda dispersa en el cuerpo y la cantidad de repeticiones
no se lee en ningún encabezado. El flujo deja de ser un árbol y se vuelve un
grafo.

### Consecuencia observable

El código funciona, pero cada lector debe rastrear los saltos para entender
cuántas veces se repite el bloque y bajo qué condiciones. Un cambio en el cuerpo
puede volver el salto infinito o inalcanzable, y el compilador no lo ayuda.
Es el llamado "código espagueti" que la programación estructurada busca evitar.

## Fundamento en el estándar C11

ISO/IEC 9899:2011 §6.8.6.1 define `goto` y admite cualquier dirección. El
teorema de Böhm–Jacopini garantiza que todo programa con `goto` puede
reescribirse con secuencia, selección e iteración. La cátedra prohíbe el uso
general (regla `0x1006h`) y tolera solo el salto hacia adelante a un bloque de
limpieza (regla `0x1013h`).

## Corrección idiomática

### ❌ Código con el antipatrón

```c
int i = 0;
repetir:
    if (i >= n)
    {
        goto fin;
    }
    procesar(valores[i]);
    i++;
    goto repetir;
fin:
    return 0;
```

### ✅ Código refactorizado

```c
for (int i = 0; i < n; i++)
{
    procesar(valores[i]);
}
return 0;
```

El `for` reúne inicialización, cota e incremento; no hay etiquetas ni saltos que
rastrear y agregar un corte equivale a modificar la condición.

## Errores típicos al compilar o ejecutar

```text
No hay error de compilación. Con -Wall, GCC y Clang pueden no advertir nada.

El riesgo es de mantenimiento: si se olvida el incremento o el goto
condicional, el lazo se vuelve infinito. Un cambio en el cuerpo puede
dejar la etiqueta fin inalcanzable.
```

## Checklist de verificación

- [ ] ¿Hay algún `goto` que salte hacia atrás?
- [ ] ¿El salto simula un lazo que podría ser `for` o `while`?
- [ ] ¿La condición de corte está dispersa en el cuerpo?
- [ ] ¿Puedo reescribir el bloque con una estructura de repetición canónica?

## Reglas relacionadas

* {ref}`0x1006h` — norma este antipatrón: prohibición general del `goto`.
* {ref}`0x1013h` — única excepción tolerada: limpieza hacia adelante.
* {ref}`0x1003h` — elegir el lazo canónico correcto.
