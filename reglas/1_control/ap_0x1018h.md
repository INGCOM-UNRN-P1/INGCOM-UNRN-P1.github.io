# Antipatrón AP-0x1018h: Ambigüedad sintáctica por omisión de llaves en condicional anidado (Dangling Else)

:::{admonition} Regla de Estilo Asociada: 0x1001h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la **[0x1001h: Todas las estructuras de control deben utilizar llaves](0x1001h.md)**.
:::

```{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1018h` | Categoría: Estructuras de Control y Lazos (0x10XX)
```


## Diagnóstico
El compilador asocia siempre 'else' con el 'if' más próximo, lo cual difiere frecuentemente de la intención del programador cuando se omiten las llaves.

## Justificación Pedagógica y de Estándar C
El código de diagnóstico `0x1018h` identifica una práctica desaconsejada en la arquitectura pedagógica de la materia.
Esta transgresión incrementa el acoplamiento, produce comportamiento indefinido o vulnera los invariantes de memoria.

## Sugerencia de Corrección
Encapsulá siempre los bloques de cada nivel condicional con llaves '{ }'.

## Ejemplos

### Código con Antipatrón (Incorrecto)
```c
if (a) if (b) foo(); else bar();
```

### Código Idiomático Refactorizado (Correcto)
```c
if (a) {
    if (b) {
        foo();
    }
} else {
    bar();
}
```
