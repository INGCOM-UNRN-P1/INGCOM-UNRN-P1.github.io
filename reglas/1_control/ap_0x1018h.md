# Antipatrón AP-0x1018h: Ambigüedad sintáctica por omisión de llaves en condicional anidado (Dangling Else)

:::{admonition} Regla de Estilo Asociada: 0x1001h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la
**[0x1001h: Todas las estructuras de control deben utilizar llaves](0x1001h.md)**.
:::

:::{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1018h` | Categoría: Estructuras de Control y Lazos (0x10XX)
:::

## Síntoma en el código del estudiante

Un `if` interno sin llaves convive con un `else` cuya indentación (o la
intención del autor) sugiere que pertenece al `if` externo:

```c
if (a)
    if (b)
        foo();
else
    bar();
```

## Diagnóstico

### Mecanismo del defecto

La gramática de C asocia cada `else` con el `if` no emparejado más cercano
(ISO/IEC 9899:2011 §6.8.4.1). Por lo tanto `else` pertenece a `if (b)`, no a
`if (a)`. La indentación no tiene valor sintáctico: el compilador ignora los
espacios y aplica la regla del "if colgado".

### Consecuencia observable

Cuando `a` es falso, `bar()` **no se ejecuta**, aunque el autor esperaba lo
contrario. Cuando `a` es verdadero y `b` falso, sí se ejecuta. El resultado es
un bug lógico que depende de la combinación de condiciones, sin ningún error de
compilación ni advertencia por defecto.

## Fundamento en el estándar C11

ISO/IEC 9899:2011 §6.8.4.1 establece la asociación del `else` con el `if` más
próximo. La cátedra elimina la ambigüedad con llaves obligatorias en cada nivel
condicional (regla `0x1001h`), de modo que la estructura escrita coincide con la
intención sin depender de la indentación.

## Corrección idiomática

### ❌ Código con el antipatrón

```c
if (a)
    if (b)
        foo();
else
    bar();
```

### ✅ Código refactorizado

```c
if (a)
{
    if (b)
    {
        foo();
    }
}
else
{
    bar();
}
```

Las llaves fijan a qué `if` pertenece cada `else`: ahora el `else` pertenece al
`if (a)` de forma explícita y `bar()` se ejecuta cuando `a` es falso.

## Errores típicos al compilar o ejecutar

```text
Con -Wdangling-else (incluida en -Wall):
warning: this 'else' clause does not guard... [-Wdangling-else]
note: ...this 'if' clause

Sin la advertencia, el comportamiento es el del 'else' más cercano;
bar() no se ejecuta cuando a es falso.
```

## Checklist de verificación

- [ ] ¿Hay `if` anidados sin llaves?
- [ ] ¿A qué `if` pertenece realmente cada `else`?
- [ ] ¿Las llaves hacen explícita la intención?
- [ ] ¿Compilé con `-Wdangling-else` o `-Wall`?
