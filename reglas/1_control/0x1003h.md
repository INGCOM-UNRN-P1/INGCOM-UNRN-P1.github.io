(0x1003h)=
# 0x1003h: Utilizá el lazo for para iteraciones con rango o contador definido y while para lazos controlados por condiciones lógicas

:::{admonition} Categoría: Estructuras de Control y Lazos (0x10XX)
:class: note
Código de regla: `0x1003h` | Soporta corrección automática: **No**
:::

:::{seealso} Antipatrones didácticos relacionados
* **[AP-0x1015h: Modificación de variable de control dentro del cuerpo del for](ap_0x1015h.md)** — el avance irregular rompe el contrato del `for`.
:::

## Enunciado normativo

> **DEBE** usarse el lazo `for` cuando la cantidad de iteraciones sea conocida
> de antemano o esté gobernada por un contador o rango. **DEBE** reservarse el
> lazo `while` para iteraciones cuya condición sea puramente lógica o se
> conozca recién en tiempo de ejecución.

## ¿Por qué existe esta regla?

### El problema

Cada lazo comunica una intención. El `for` dice "recorro un rango conocido" y
reúne inicialización, cota e incremento en una sola línea; el lector ve todo el
contrato de una vez. El `while` dice "repito mientras se cumpla una condición"
y separa el avance del encabezado, porque el avance puede depender del cuerpo.

Usar el lazo equivocado esconde esa intención. Un `for` con condición compuesta
o con cláusulas vacías es un `while` disfrazado; un `while` que cuenta
iteraciones obliga a buscar el incremento dentro del cuerpo y es la causa
habitual del lazo infinito por olvido.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Lazo infinito | `while` de conteo al que se le olvida el incremento. |
| Legibilidad | No se distingue a simple vista si el lazo recorre un rango o espera un evento. |
| Mantenibilidad | Cambiar la cota obliga a ubicar y tocar el cuerpo, no el encabezado. |
| Bug lógico | Un `for` con condición compuesta oculta varias condiciones de corte. |

### Fundamento en el estándar y en la cátedra

ISO/IEC 9899:2011 §6.8.5.3 describe el `for` como azúcar sintáctico de un
`while`; son equivalentes en poder expresivo. La cátedra elige uno u otro por
su valor comunicativo: `for` para conteos acotados, `while` para condiciones.
Se alinea con {ref}`0x100Fh`, que prohíbe cotas compuestas en el `for`.

## Alcance y excepciones

- **`for`:** rangos, arreglos, conteos con incremento regular.
- **`while`:** lectura hasta centinela, validación de entrada, espera de evento.
- **`do-while`:** cuando el cuerpo debe ejecutarse al menos una vez, por
  ejemplo pedir datos hasta que sean válidos.
- No hay una forma "más rápida": ambos compilan a lo mismo.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — `for` para una condición lógica

```c
for (int n = leer(); n != 0; n = leer())
{
    procesar(n);
}
```

Por qué falla: no hay contador ni rango; la cantidad de iteraciones se decide
por el valor leído. El `for` fuerza a duplicar la lectura en la inicialización y
en el incremento, y si el paso cambia hay que tocar dos lugares.

### ❌ Contraejemplo 2 — `while` usado para contar

```c
int i = 0;
while (i < cantidad)
{
    total += valores[i];
}
```

Por qué falla: falta `i++`. El lazo nunca termina y accede siempre a
`valores[0]`. El `for` habría impedido esa omisión porque el incremento es
obligatorio en la sintaxis.

### ✅ Ejemplo conforme 1 — `for` para recorrer un rango

```c
for (size_t i = 0; i < cantidad; i++)
{
    total += valores[i];
}
```

Inicialización, cota e incremento viven juntos; el recorrido se lee completo en
el encabezado y no hay forma de olvidar el avance.

### ✅ Ejemplo conforme 2 — `while` para leer hasta centinela

```c
int n = leer();
while (n != 0)
{
    procesar(n);
    n = leer();
}
```

La condición depende del dato leído, no de un contador; el `while` es la
elección idiomática. El avance está en el cuerpo porque la lectura es la
operación que define el corte.

### ⚠️ Casos límite

- **Rango `[a, b)` vs `[a, b]`:** con `for` la cota semiabierta `i < b` es la
  forma segura frente al off-by-one (ver {ref}`0x100Fh`).
- **Lazo que se ejecuta al menos una vez:** el `do-while` es el único que lo
  garantiza; no forzarlo con `while` y una lectura previa duplicada.
- **`for` sin uso del índice:** si el contador no se usa, probablemente el
  lazo debería ser un `while` con condición lógica.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Regla `0x1003h`: elección de lazo. |
| Revisión manual | — | `for` con condición compuesta o `while` sin avance. |
| `gcc` | `gcc -Wall -Wextra -O2` | `warning` de variable puede quedar sin cambiar. |

## Checklist de autocontrol

- [ ] ¿Puedo decir en una frase si el lazo recorre un rango o espera un evento?
- [ ] Si es un rango, ¿usé `for` con el incremento en el encabezado?
- [ ] Si es una condición lógica, ¿usé `while` y el avance está en el cuerpo?
- [ ] ¿Necesito que el cuerpo se ejecute al menos una vez? Entonces `do-while`.

## Reglas relacionadas

* {ref}`0x100Fh` — la cota del `for` debe ser simple; si no, pasá a `while`.
* {ref}`0x1002h` — elegir el lazo correcto reduce la necesidad de `break`.
* {ref}`0x1010h` — el `do-while` exige llaves en su cuerpo.
