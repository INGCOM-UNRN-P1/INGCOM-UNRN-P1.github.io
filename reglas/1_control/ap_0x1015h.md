(ap_0x1015h)=
# Antipatrón AP-0x1015h: Modificación de variable de control dentro del cuerpo del for

:::{admonition} Regla de Estilo Asociada: 0x1003h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la
**[0x1003h: Utilizá el lazo for para iteraciones con rango o contador definido y while para lazos controlados por condiciones lógicas](0x1003h.md)**.
:::

:::{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x1015h` | Categoría: Estructuras de Control y Lazos (0x10XX)
:::

## Síntoma en el código del estudiante

El cuerpo del `for` altera la variable de control, que ya se modifica en el
incremento del encabezado:

```c
for (int i = 0; i < n; i++)
{
    if (condicion)
    {
        i += 2;
    }
}
```

## Diagnóstico

### Mecanismo del defecto

El `for` reserva la modificación del contador para su cláusula de incremento.
Cuando el cuerpo también la modifica, hay dos dueños del avance: el lector no
puede calcular cuántas iteraciones habrá mirando el encabezado, y una misma
ejecución puede saltar pasos o retroceder sin que se vea.

### Consecuencia observable

El número de iteraciones deja de estar determinado por `i < n`. Aparecen
comportamientos tipo "recorrió la mitad" o "se pasó del límite", y el acceso a
`valores[i]` puede salirse del arreglo. El lazo se vuelve difícil de razonar y
de probar.

## Fundamento en el estándar C11

ISO/IEC 9899:2011 §6.8.5.3 permite modificar cualquier variable dentro del
cuerpo, incluida la de control; la restricción es de diseño. La cátedra exige
que el avance regular quede en el encabezado. Cuando el avance depende de
condiciones dinámicas, la estructura adecuada es el `while`, donde el contador
es parte de la lógica (regla `0x1003h`).

## Corrección idiomática

### ❌ Código con el antipatrón

```c
for (int i = 0; i < n; i++)
{
    if (condicion)
    {
        i += 2;
    }
    procesar(valores[i]);
}
```

### ✅ Código refactorizado

```c
int i = 0;
while (i < n)
{
    if (condicion)
    {
        i += 2;
    }
    else
    {
        i++;
    }
    procesar(valores[i]);
}
```

El `while` deja el avance en el cuerpo, que es donde realmente se decide. Ahora
el lector sigue todos los cambios del contador en un mismo lugar.

## Errores típicos al compilar o ejecutar

```text
No hay error de compilación. El lazo puede:
- saltear elementos sin procesar,
- saltar el último índice,
- acceder a valores[i] con i >= n si el salto cruza la cota.

Con -fsanitize=address puede reportar stack-buffer-overflow en el acceso.
```

## Checklist de verificación

- [ ] ¿El cuerpo del `for` modifica la variable de control?
- [ ] ¿El avance es regular o depende de una condición?
- [ ] Si es irregular, ¿cambié la estructura a `while`?
- [ ] ¿Puedo predecir las iteraciones mirando solo el encabezado?

## Reglas relacionadas

* {ref}`0x1003h` — norma este antipatrón: elección del lazo según el control.
* {ref}`0x100Fh` — la condición del `for` debe ser una cota simple.
* {ref}`0x300Ch` — verificar límites antes de acceder al arreglo.
