(0x1006h)=
# 0x1006h: No utilizar la instrucción goto

:::{admonition} Categoría: Estructuras de Control y Lazos (0x10XX)
:class: note
Código de regla: `0x1006h` | Soporta corrección automática: **No**
:::

:::{seealso} Antipatrones didácticos relacionados
* **[AP-0x1019h: Uso de salto goto hacia atrás vulnerando programación estructurada](ap_0x1019h.md)** — el salto simula un lazo y destruye el flujo estructurado.
:::

## Enunciado normativo

> **NO DEBE** usarse la instrucción `goto` en el código de la cátedra. Toda
> repetición o salto condicional **DEBE** expresarse con las estructuras de
> control estándar (`if`, `for`, `while`, `do-while`, `switch`).

## ¿Por qué existe esta regla?

### El problema

`goto` permite saltar a cualquier etiqueta del mismo cuerpo, hacia adelante o
hacia atrás, sin pasar por las condiciones que las otras estructuras imponen.
El flujo deja de ser un árbol y se vuelve un grafo: para saber qué se ejecuta
después de una línea hay que buscar todas las etiquetas y todos los saltos.

Ese costo lo paga cada lector, cada vez. El teorema de la programación
estructurada de Böhm–Jacopini demuestra que todo programa con `goto` puede
reescribirse con secuencia, selección e iteración; por lo tanto el `goto` no
aporta poder expresivo, solo oscurecimiento.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Código espagueti | Saltos cruzados que hacen imposible seguir el flujo linealmente. |
| Depuración | El contador de programa salta sin relación aparente con la línea previa. |
| Mantenibilidad | Mover una sentencia puede romper una etiqueta distante. |
| Inicialización | Un salto hacia atrás puede reintroducir un estado ya procesado. |

### Fundamento en el estándar y en la cátedra

ISO/IEC 9899:2011 §6.8.6.1 define `goto`; el estándar lo permite, y de hecho
admite el patrón de liberación centralizada. La cátedra adopta la prohibición
general para forzar el razonamiento estructurado en el curso introductorio. La
regla más específica {ref}`0x1013h` admite una única excepción acotada; ante
cualquier duda, consultar con la cátedra.

## Alcance y excepciones

- Regla general: `goto` prohibido.
- **Única excepción admitida:** el salto **hacia adelante** a un bloque terminal
  de liberación de recursos, descripto en {ref}`0x1013h`.
- `break` y `continue` no son `goto`; se norman en {ref}`0x1002h`.
- El `switch` no requiere `goto`; usa `break` (ver {ref}`0x1008h`).

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — `goto` simulando un lazo

```c
int i = 0;
repetir:
    if (i >= n)
    {
        goto fin;
    }
    procesar(valores[i]);
    i++;
    goto repetir;
fin:
    return 0;
```

Por qué falla: un lazo `for` expresa lo mismo en tres líneas. Acá el flujo
depende de dos etiquetas y tres saltos; agregar un `continue` equivalente
requiere otra etiqueta.

### ❌ Contraejemplo 2 — `goto` cruzando la inicialización

```c
goto saltar;
int total = 0;
saltar:
    printf("%d\n", total);
```

Por qué falla: el salto omite la inicialización y `total` se lee con un valor
indeterminado. Es comportamiento indefinido (ISO/IEC 9899:2011 §6.2.4).

### ✅ Ejemplo conforme 1 — lazo estructurado equivalente

```c
for (int i = 0; i < n; i++)
{
    procesar(valores[i]);
}
```

El encabezado reúne inicialización, cota e incremento; no hay etiquetas ni
saltos que rastrear.

### ✅ Ejemplo conforme 2 — salida temprana estructurada

```c
bool procesar_todo(const int valores[], size_t n)
{
    for (size_t i = 0; i < n; i++)
    {
        if (!procesar(valores[i]))
        {
            return false;
        }
    }
    return true;
}
```

El retorno anticipado reemplaza al `goto` de error; es una salida legítima
dentro de una función corta (ver {ref}`0x2001h`).

### ⚠️ Casos límite

- **Limpieza centralizada:** el único patrón tolerado es el de {ref}`0x1013h`;
  si hay múltiples recursos, evaluar una función de limpieza.
- **Punteros y liberación:** en vez de `goto`, se puede encapsular la limpieza
  en una función y llamarla antes de retornar.
- **`goto` generado por macros:** prohibido igual; la macro debe reescribirse.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Regla `0x1006h`: uso de `goto`. |
| Búsqueda | `grep -n "goto" archivo.c` | Toda aparición es una violación. |
| `gcc` | `gcc -Wall -Wextra` | No la señala: `goto` es C válido. |

## Checklist de autocontrol

- [ ] ¿Queda algún `goto` y su etiqueta en el archivo?
- [ ] ¿El lazo que el `goto` simulaba puede escribirse con `for` o `while`?
- [ ] Si hay limpieza de recursos, ¿usé el patrón de {ref}`0x1013h`?
- [ ] ¿Las salidas tempranas usan `return` en lugar de saltos?
