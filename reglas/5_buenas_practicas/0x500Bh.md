(0x500Bh)=
# 0x500Bh: Inclusión obligatoria de cabeceras estándar para funciones de la biblioteca C

:::{admonition} Categoría: Compilación y Buenas Prácticas de Ingeniería (0x50XX)
:class: note
Código de regla: `0x500Bh` | Soporta corrección automática: **No**
:::

:::{seealso} Antipatrón didáctico relacionado
* **[AP-0x500Bh: Redefinición de identificadores de funciones estándar de la biblioteca C](ap_0x500Bh.md)** — colisionar con la libc en lugar de incluirla.
:::

## Enunciado normativo

> **DEBE** incluirse explícitamente la cabecera que declara cada función de la
> biblioteca estándar antes de invocarla: `printf`/`scanf` (`<stdio.h>`),
> `malloc`/`free` (`<stdlib.h>`), `strlen`/`strcmp` (`<string.h>`).

## ¿Por qué existe esta regla?

### El problema

El compilador conoce las funciones por su **declaración**, no por su nombre. Sin
la cabecera adecuada, en C89 se asumía una declaración implícita `int f()`; C99
eliminó esa concesión y C11 la considera directamente inválida. Cuando el
programa compila por descuido, el compilador supone que la función devuelve
`int` y no revisa los argumentos. Para una función que en realidad retorna
`double` o un puntero, esa suposición genera corrupción silenciosa. Incluir la
cabecera es lo que habilita la verificación de formatos de `printf` y de tipos.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Compilación | `implicit declaration of function`; en GCC moderno es error. |
| Comportamiento indefinido | Se asume retorno `int` para funciones que devuelven puntero o `double`. |
| Bug silencioso | Sin `<stdio.h>`, `printf` con `%f` no se valida contra el argumento. |

### Fundamento en el estándar y en la cátedra

ISO/IEC 9899:2011 §6.5.2.2 rige las llamadas a función: sólo son válidas si
existe una declaración en alcance. C99 suprimió la regla de «tipo `int`
implícito». La cátedra exige la inclusión explícita porque el código se compila
con `-Werror` y porque `-Wformat` sólo actúa con `<stdio.h>` presente.

## Alcance y excepciones

Aplica a toda función de la biblioteca estándar. La cabecera debe incluirse en
cada unidad de traducción que la use, no basta que otro `.c` la incluya.
**Excepción de enlace:** `<math.h>` declara `sin`, `sqrt`, etc., pero en Linux
hay que agregar `-lm` al enlazar; la cabecera no reemplaza la biblioteca.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — `printf` sin `<stdio.h>`

```c
int main(void)
{
    printf("Hola\n");
    return 0;
}
```

Por qué falla: sin declaración, el compilador asume `int printf()`. Con
`-Werror` la compilación se detiene; sin él, el formato no se valida y el
comportamiento queda librado a la suerte.

### ❌ Contraejemplo 2 — `malloc` sin `<stdlib.h>`

```c
int *crear(size_t n)
{
    int *v = malloc(n * sizeof(*v));
    return v;
}
```

Por qué falla: `malloc` devuelve `void *`, pero sin la cabecera el compilador
cree que devuelve `int`. En una máquina de 64 bits el puntero de 8 bytes se
trunca a 4 y el acceso posterior corrompe memoria.

### ✅ Ejemplo conforme 1 — Cabeceras explícitas

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    char *s = malloc(16);
    if (s == NULL) {
        return 1;
    }
    strcpy(s, "hola");
    printf("%s\n", s);
    free(s);
    return 0;
}
```

Cada función tiene su declaración en alcance; el compilador valida argumentos,
formatos y tipos de retorno, y `-Werror` convierte cualquier descuido en error.

### ✅ Ejemplo conforme 2 — Cabecera propia primero y la correcta después

```c
#include "lista.h"

#include <stddef.h>
#include <stdlib.h>

nodo_t *nodo_crear(int valor)
{
    nodo_t *n = malloc(sizeof(*n));
    if (n != NULL) {
        n->dato = valor;
    }
    return n;
}
```

La cabecera del propio módulo va primero para detectar faltantes
({ref}`0x0011h`) y luego se incluye `<stddef.h>` por `size_t` y `<stdlib.h>` por
`malloc`. Es el orden que pide {ref}`0x5005h`.

### ⚠️ Casos límite

- **`<math.h>` y `-lm`:** la declaración está en la cabecera, pero el enlace
  necesita `-lm` en Linux; sin ella el error es del enlazador.
- **Funciones en varias cabeceras:** `size_t` vive en `<stddef.h>`, no en
  `<stdlib.h>`; incluí la que corresponde a cada uso.
- **Funciones POSIX:** `strdup` o `getline` requieren la macro de entorno
  adecuada además de su cabecera, y no son ISO C.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Reporta `0x500Bh` ante llamadas a la biblioteca sin su cabecera. |
| `gcc` / `clang` | `gcc -std=c11 -Wall -Wextra -Werror -pedantic archivo.c` | `implicit declaration of function 'printf'`. |

## Checklist de autocontrol

- [ ] ¿Cada función de la biblioteca invocada tiene su `#include` en este archivo?
- [ ] ¿Incluí `<stdio.h>`, `<stdlib.h>`, `<string.h>` según lo que uso?
- [ ] ¿Comprobé que `-Werror` no reporta declaraciones implícitas?
- [ ] ¿La cabecera propia está en primer lugar entre las de usuario?
