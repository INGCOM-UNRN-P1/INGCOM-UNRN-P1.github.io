(0x200Ch)=
# 0x200Ch: Cada función debe tener a lo sumo un return

:::{admonition} Categoría: Funciones, contratos y modularizacion (0x20XX)
:class: note
Código de regla: `0x200Ch` | Soporta corrección automática: **No**
:::

:::{seealso} Refactorización asociada
* {ref}`refactorizacion-unico-retorno` — Patrón de retorno único y retornos anticipados.
:::

## Enunciado normativo

> **DEBE** concentrarse el resultado de la función en una única variable y
> ejecutar un solo `return` al final. La única excepción son las cláusulas de
> guarda de validación inicial, autorizadas por {ref}`0x2001h`.

## ¿Por qué existe esta regla?

### El problema

Con varios `return` dispersos, cada uno es una salida que hay que auditar: si
alguno olvida liberar un recurso o normalizar el resultado, aparece un camino
distinto sin que se note. Con un único `return` final, el resultado se construye
paso a paso y se entrega una sola vez; ese punto es el lugar natural para la
limpieza y la verificación final.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Fugas de recursos | Una salida anticipada omite el `free` o el `fclose`. |
| Bug silencioso | Un `return` temprano devuelve un valor no normalizado. |
| Legibilidad | Hay que rastrear todas las salidas para saber qué devuelve. |
| Testing | Los caminos de salida múltiples multiplican los casos a cubrir. |

### Fundamento en el estándar y en la cátedra

C11 admite `return` en cualquier punto del cuerpo (§6.8.6.4); no hay nada
técnico que impida varios. La regla es una convención de la cátedra para que el
flujo sea predecible y la limpieza única. Convive con {ref}`0x2001h`: las
guardas de validación inicial se aceptan porque no hay recursos adquiridos. La
prioridad es guardas al principio, un solo `return` después.

## Alcance y excepciones

Aplica a funciones con lógica y recursos. **No** se aplica cuando la estructura
natural es un `switch` que retorna por `case`, aunque se prefiere asignar a la
variable de resultado. **Excepciones:** guardas ({ref}`0x2001h`), `switch` de
despacho y recursivas puras con ramas de expresión simple.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Retorno múltiple con limpieza olvidada

```c
int cargar(const char *ruta, struct tabla_t *t)
{
    FILE *f = fopen(ruta, "r");
    if (f == NULL) {
        return ERROR_APERTURA;
    }
    if (leer(f, t) != 0) {
        return ERROR_LECTURA;
    }
    fclose(f);
    return OK;
}
```

La lectura fallida retorna sin cerrar el archivo: la limpieza quedó atada al
camino feliz.

### ❌ Contraejemplo 2 — Cada rama retorna una vez

```c
int clasificar(int valor)
{
    if (valor < 0) {
        return -1;
    }
    if (valor == 0) {
        return 0;
    }
    return 1;
}
```

Correcto, pero el resultado queda repartido; agregar una normalización final
obligaría a repetirla en cada rama.

### ✅ Ejemplo conforme 1 — Resultado único y limpieza centralizada

```c
int cargar(const char *ruta, struct tabla_t *t)
{
    int resultado = OK;
    FILE *f = fopen(ruta, "r");
    if (f == NULL) {
        return ERROR_APERTURA;
    }
    if (leer(f, t) != 0) {
        resultado = ERROR_LECTURA;
    }
    if (fclose(f) != 0) {
        resultado = ERROR_CIERRE;
    }
    return resultado;
}
```

La guarda de apertura es la única salida anticipada; todos los caminos liberan.

### ✅ Ejemplo conforme 2 — Variable de resultado para clasificar

```c
int clasificar(int valor)
{
    int resultado;
    if (valor < 0) {
        resultado = -1;
    } else if (valor == 0) {
        resultado = 0;
    } else {
        resultado = 1;
    }
    return resultado;
}
```

El valor se decide en la cadena de condiciones y se entrega en un único punto.

### ⚠️ Casos límite

- **Guardas iniciales:** `if (p == NULL) { return ERROR; }` no cuenta como
  retorno múltiple problemático ({ref}`0x2001h`).
- **`switch` de retorno:** evaluá convertirlo a asignaciones sobre el resultado.

| :--- | :--- | :--- |

## Checklist de autocontrol

- [ ] ¿Concentré el resultado en una variable y lo devolví al final?
- [ ] ¿Mis únicas salidas anticipadas son guardas de validación?
- [ ] ¿Todos los caminos liberan los recursos adquiridos?
