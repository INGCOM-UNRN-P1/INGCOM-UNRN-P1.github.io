(0x300Dh)=
# 0x300Dh: Utilizá enum en lugar de "números mágicos" para conjuntos de estados y valores constantes

:::{admonition} Categoría: Punteros y Gestión de Memoria (0x30XX)
:class: note
Código de regla: `0x300Dh` | Soporta corrección automática: **No**
:::

:::{seealso} Antipatrón didáctico relacionado
* **[AP-0x300Dh: Número mágico literal en condición lógica](ap_0x300Dh.md)** — comparar un estado contra un entero sin nombre.
:::

## Enunciado normativo

> Los conjuntos de estados y de valores constantes relacionados **DEBEN**
> declararse con `enum` (o con constantes simbólicas con nombre) y **NO DEBEN**
> aparecer como literales numéricos dispersos en el código.

## ¿Por qué existe esta regla?

### El problema

Un literal como `if (estado == 2)` no dice qué representa `2`: el significado vive
sólo en la cabeza del autor y quien escribe puede confundirlo con el `3`. `enum`
introduce un conjunto de constantes con nombre junto al tipo, y así el
compilador, el depurador y el lector comparten la misma semántica.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Bug lógico | Dos estados se confunden porque `1` y `2` son intercambiables a la vista. |
| Mantenibilidad | Insertar un estado intermedio obliga a renumerar todos los usos. |
| Depuración | El depurador muestra `2` en lugar de `ESTADO_LISTO`. |

### Fundamento en el estándar y en la cátedra

C11 §6.7.2.2 define `enum` como un conjunto de constantes enteras con nombre. La
cátedra lo adopta para todo grupo de valores mutuamente excluyentes y lo prefiere
sobre `#define` porque agrupa los valores y les da un tipo.

## Alcance y excepciones

Aplica a estados, modos, códigos de error y conjuntos de valores relacionados.
**No** aplica a constantes de dominio aisladas (por ejemplo una longitud máxima),
donde corresponde un `#define` o una `const` conforme a {ref}`0x0008h`.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Comparación contra un literal

```c
if (estado == 2)
{
    reiniciar();
}
```

Por qué falla: no se sabe qué es `2`. Si el conjunto de estados cambia, el
significado se pierde y la comparación puede pasar a referirse a otro estado. El
nombre del estado debería estar en el código.

### ❌ Contraejemplo 2 — Constantes relacionadas definidas por separado

```c
#define ESTADO_NUEVO 0
#define ESTADO_LISTO 1
#define ESTADO_ERROR -1
void avanzar(int estado)
{
    if (estado == ESTADO_LISTO)
    {
        siguiente_paso();
    }
}
```

Por qué falla: los valores se declaran por separado, sin un tipo que los agrupe.
`avanzar` acepta cualquier `int`, incluidos valores ajenos al conjunto, y el
compilador no puede advertirlo.

### ✅ Ejemplo conforme 1 — `enum` con tipo propio

```c
typedef enum estado
{
    ESTADO_NUEVO,
    ESTADO_LISTO,
    ESTADO_ERROR
} estado_t;
void avanzar(estado_t estado)
{
    if (estado == ESTADO_LISTO)
    {
        siguiente_paso();
    }
}
```

El conjunto y su tipo se declaran juntos. El lector ve el nombre del estado, el
depurador también, y la firma comunica que sólo se aceptan valores del conjunto.
El alias respeta {ref}`0x3004h`.

### ✅ Ejemplo conforme 2 — `enum` para índices simbólicos

```c
typedef enum campo
{
    CAMPO_NOMBRE = 0,
    CAMPO_EDAD,
    CAMPO_CIUDAD,
    CAMPO_CANTIDAD
} campo_t;
char *etiquetas[CAMPO_CANTIDAD];
etiquetas[CAMPO_EDAD] = "Edad";
```

`CAMPO_CANTIDAD` cierra el conjunto y expresa la dimensión del arreglo, evitando
un literal de tamaño. Los índices se leen con nombre y el arreglo no puede
desincronizarse sin advertirlo. Se refuerza con {ref}`0x0038h`.

### ⚠️ Casos límite

- **Valores serializados:** si el número se guarda en un archivo o protocolo, no
  renumera el `enum` sin actualizar el formato; documentá la correspondencia.
- **`switch`:** todo `switch` sobre un `enum` debe cubrir los casos y cerrar con
  `default`, conforme a {ref}`0x1008h`.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Comparación de estado contra literal numérico. |
| `gcc` / `clang` | `gcc -Wall -Wextra -std=c11 -Wswitch-enum ...` | `case` faltante en `switch` sobre `enum`. |
| Revisión manual | — | Literales repetidos que representan el mismo estado. |

## Checklist de autocontrol

- [ ] ¿Los estados forman un `enum` con nombre?
- [ ] ¿El `enum` tiene un alias `_t`?
- [ ] ¿Evité comparar estados contra literales?
- [ ] ¿Usé el último miembro como cantidad cuando aplica?
