(ap_0x0004b)=
# Antipatrón AP-0x0004b: Lectura de variable local no inicializada

:::{admonition} Regla de Estilo Asociada: 0x0004h
:class: tip
La transgresión descripta en este antipatrón se encuentra normada por la **[0x0004h: Un espacio antes y después de cada operador binario](0x0004h.md)**.
:::

:::{admonition} Diagnóstico de Antipatrón
:class: warning
Código de auditoría: `AP-0x0004b` | Categoría: Sintaxis Básica y Nomenclatura (0x00XX)
:::

## Síntoma en el código del estudiante

La variable se lee antes de recibir un valor, típicamente en un operador
compuesto:

```c
int acumulador;
acumulador += valor;
```

La señal es una declaración sin `=` seguida de una operación que **usa** la
variable a la derecha: `+=`, `-=`, `++`, `printf` o una comparación. A
diferencia de AP-0x0003b, la declaración sí está al inicio del bloque; el
defecto es que nunca se le dio un valor conocido.

## Diagnóstico

### Mecanismo del defecto

`acumulador += valor;` equivale a `acumulador = acumulador + valor;`: el
`acumulador` de la derecha se lee primero. Como la variable es automática, vive
en la pila y no se inicializa a cero; conserva el valor que dejó el uso previo
de esa dirección de memoria. La lectura de un objeto automático sin
inicializador explícito es un valor indeterminado (C11 §6.7.9p10), y operar con
él puede dar comportamiento indefinido. La suma arranca de una base arbitraria
en vez de cero.

### Consecuencia observable

`gcc -Wall -Wextra` emite `warning: 'acumulador' is used uninitialized` cuando
puede seguir el flujo. Si no lo detecta, la suma da un resultado distinto en
cada ejecución, porque depende del contenido residual de la pila. En programas
con esa base aleatoria, el bug es intermitente y difícil de reproducir.

## Fundamento en el estándar C11

C11 §6.7.9p10 dispone que un objeto de duración automática sin inicializador
explícito tiene valor indeterminado. §6.2.4 describe la duración de
almacenamiento automática y §6.3.1 las conversiones que no pueden aplicarse a
valores indeterminados sin riesgo. La cátedra lo prohibe porque todo cálculo
debe partir de un valor conocido, tal como exige {ref}`0x0003h`.

## Corrección idiomática

### ❌ Código con el antipatrón

```c
int acumulador;
acumulador += valor;
```

### ✅ Código refactorizado

```c
int acumulador = 0;
acumulador += valor;
```

Por qué mejora: el inicializador fija la base del acumulador en cero y elimina
la dependencia del contenido residual de la pila. El operador compuesto ahora
lee un valor conocido.

## Errores típicos al compilar o ejecutar

```text
warning: 'acumulador' is used uninitialized [-Wuninitialized]
warning: 'acumulador' may be used uninitialized [-Wmaybe-uninitialized]
```

## Checklist de verificación

- [ ] Ninguna variable se lee antes de recibir un valor conocido.
- [ ] Los acumuladores y contadores empiezan en `0`.
- [ ] Los punteros empiezan en `NULL` ({ref}`0x3008h`).
- [ ] Composiciones como `+=` operan sobre un valor ya inicializado.
- [ ] Compilé con `-Wall -Wextra` y sin advertencias de `uninitialized`.

## Reglas relacionadas

* {ref}`0x0003h` — inicializar toda variable a un valor conocido.
* {ref}`0x0004h` — espaciado de los operadores binarios y compuestos.
* {ref}`0x3008h` — inicializar y comparar punteros con `NULL`.
* {ref}`0x2007h` — mantener el alcance de las variables al mínimo.
* {ref}`0x301Ah` — uso idiomático de `bool`, `true` y `false`.
