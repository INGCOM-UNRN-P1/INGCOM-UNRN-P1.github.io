(0x0010h)=
# 0x0010h: Control de longitud máxima de archivos de código (máx 500 líneas)

:::{admonition} Categoría: Sintaxis Básica y Nomenclatura (0x00XX)
:class: note
Código de regla: `0x0010h` | Soporta corrección automática: **No**
:::

## Enunciado normativo

> **NO DEBE** superarse las 500 líneas por archivo fuente `.c` o de cabecera
> `.h`. Si un módulo excede ese tamaño, **DEBE** dividirse en módulos
> cohesivos.

El límite se mide sobre el archivo completo.

## ¿Por qué existe esta regla?

### El problema

Un archivo largo suele ser un archivo con demasiadas responsabilidades. Al
leerlo, el estudiante no puede mantener en la cabeza todas las funciones y
tipos que define, y cualquier cambio exige recompilar y volver a entender un
contexto enorme. La longitud del archivo es un síntoma medible de acoplamiento
bajo y cohesión baja.

La división en módulos, además, obliga a decidir qué es público y qué es
privado, lo que prepara el terreno para los TAD de {ref}`0x0035h`.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Compilación | Ninguna: el compilador acepta archivos de miles de líneas. |
| Tiempo de compilación | Cada cambio menor recompila todo el archivo. |
| Mantenibilidad | Varias responsabilidades conviven y sus cambios se interfieren. |
| Reutilización | No se puede llevar una parte sin arrastrar todo el archivo. |
| Legibilidad | Es imposible ubicar una función rápidamente. |

### Fundamento en el estándar y en la cátedra

El estándar organiza el programa en unidades de traducción (§5.1.1) y no fija
tamaños. La cátedra adopta 500 líneas como umbral razonable para un módulo de
cátedra y como disparador de modularización, en línea con
{ref}`0x6003h` (funciones de una sola idea) y {ref}`0x2005h`
(responsabilidad única).

## Alcance y excepciones

Aplica a archivos escritos por el estudiante. Las tablas de datos generadas
(por ejemplo, una tabla de senos o de caracteres) y el código autogenerado
pueden exceder el límite si están claramente identificados. Un archivo de
pruebas puede ser más largo si agrupa casos independientes.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Todo el trabajo en un archivo

```text
todo_junto.c (950 líneas)
```

Por qué falla: contiene el TAD pila, el TAD cola, la interfaz de usuario y
las pruebas en el mismo archivo; ningún equipo puede modificarlo en paralelo
sin conflictos.

### ❌ Contraejemplo 2 — Cabecera que declara todo el sistema

```c
/* sistema.h: 800 líneas */
/* pila */
typedef struct pila pila_t;
void pila_push(pila_t *p, int x);
/* cola */
typedef struct cola cola_t;
void cola_push(cola_t *c, int x);
/* ...200 prototipos más... */
```

Por qué falla: la cabecera se convierte en un catálogo global; cualquier
módulo que la incluya arrastra dependencias que no necesita.

### ✅ Ejemplo conforme 1 — Módulos separados por TAD

```text
modulo_pila.c   (120 líneas)
modulo_pila.h   ( 25 líneas)
modulo_cola.c   (140 líneas)
modulo_cola.h   ( 28 líneas)
```

Justificación: cada archivo tiene una responsabilidad clara, se compila por
separado y su cabecera expone solo la interfaz necesaria.

### ✅ Ejemplo conforme 2 — División de un archivo en riesgo

```c
// antes: procesar.c (620 líneas)
// despues:
//   entrada.c   -> lectura y validacion
//   calculo.c   -> logica de negocio
//   salida.c    -> formateo e impresion
```

Justificación: se separaron tres responsabilidades; el conteo baja del umbral
y cada módulo se prueba de forma aislada.

### ⚠️ Casos límite

- **Tablas de datos:** un arreglo `static const` de miles de entradas es
  legítimo; conviene moverlo a un archivo propio de datos.
- **Generación automática:** el código de un parser generado por herramienta
  se exceptúa, pero se aísla del código escrito a mano.
- **Archivos de prueba:** pueden superar el límite si cada prueba es
  independiente y el archivo sigue siendo navegable.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `wc` | `wc -l *.c *.h` | Archivos por encima de 500 líneas. |
| `gaff` | `gaff check archivo.c` | Longitud máxima de archivo excedida. |
| Revisión manual | — | Varios TAD o niveles de abstracción en un mismo archivo. |

## Checklist de autocontrol

- [ ] ¿El archivo tiene una única responsabilidad?
- [ ] ¿Supera las 500 líneas?
- [ ] ¿Puedo separarlo en módulos con cabeceras propias?
- [ ] ¿Aislé las tablas y el código generado?

## Reglas relacionadas

* {ref}`0x6003h` — funciones de una sola idea y hasta 25 líneas.
* {ref}`0x2005h` — responsabilidad única por función.
* {ref}`0x0035h` — TAD con punteros opacos y cabeceras mínimas.
* {ref}`0x5005h` — estructura estándar de los archivos `.c`.
* {ref}`0x000Eh` — separar módulos también separa funciones.
