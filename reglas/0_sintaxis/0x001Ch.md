(0x001Ch)=
# 0x001Ch: Espacio en blanco obligatorio tras la coma separadora en listas y argumentos

:::{admonition} Categoría: Sintaxis Básica y Nomenclatura (0x00XX)
:class: note
Código de regla: `0x001Ch` | Soporta corrección automática: **Sí**
:::

## Enunciado normativo

> **DEBE** dejarse exactamente un espacio en blanco después de toda coma que
> separe argumentos, parámetros, declaradores o elementos de una lista.
> **NO DEBE** pegarse el elemento siguiente a la coma.

La coma en sí no lleva espacio anterior ({ref}`0x0019h`).

## ¿Por qué existe esta regla?

### El problema

La coma es el separador más frecuente del código. Sin espacio posterior,
`foo(x,y,z)` forma un bloque compacto donde los argumentos no se distinguen.
Con exactamente un espacio, los elementos se separan y el ojo enumera la
lista sin esfuerzo, como en el texto en prosa.

El espacio posterior es también una regla natural: en la escritura, la coma
se escribe pegada a la palabra anterior y seguida de un espacio.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Compilación | Ninguna: el espacio no cambia la lista. |
| Legibilidad | Los argumentos se confunden entre sí en listas largas. |
| Consistencia | Convive `f(a, b)` con `g(x,y,z)`. |
| Depuración | Es más difícil ubicar visualmente un argumento puntual. |
| Revisión | El espaciado irregular distrae de la lógica de la llamada. |

### Fundamento en el estándar y en la cátedra

El estándar trata la coma como separador de listas (§6.7.6, §6.5.2) y
permite cualquier espaciado (§6.4). La cátedra exige un espacio posterior
para que las listas se lean como enumeraciones, complementando
{ref}`0x0019h` y {ref}`0x002Bh`.

## Alcance y excepciones

Aplica a listas de argumentos, parámetros, declaradores, inicializadores y
elementos de `enum`. Dentro de una cadena literal la coma es texto y no se
altera. La coma del operador (`(a, b)`) sigue el mismo criterio de lista.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Lista sin espacios

```c
int a,b = 0;
foo(x,y,z);
```

Por qué falla: los elementos quedan pegados; en la declaración, además,
`a,b` parece una sola construcción.

### ❌ Contraejemplo 2 — Espaciado irregular

```c
calcular( base,tasa , plazo );
```

Por qué falla: la primera coma no tiene espacio posterior, la segunda tiene
uno anterior (que viola {ref}`0x0019h`) y el paréntesis tiene espacios
internos ({ref}`0x001Dh`); todo el espaciado es inconsistente.

### ✅ Ejemplo conforme 1 — Lista separada

```c
int a, b = 0;
foo(x, y, z);
```

Justificación: cada coma queda adherida al elemento anterior y seguida de un
único espacio, de modo que los elementos se enumeran de un vistazo.

### ✅ Ejemplo conforme 2 — Firma y llamada coherentes

```c
static int calcular_interes(int capital, double tasa, int plazo_meses)
{
    return capital;
}

int resultado = calcular_interes(monto, 0.05, 12);
```

Justificación: la firma y la llamada usan el mismo espaciado, lo que
refuerza la correspondencia posicional entre parámetros y argumentos.

### ⚠️ Casos límite

- **Comas en cadenas:** `printf("a,b")` conserva la coma sin espacio porque
  es contenido, no separador.
- **Declaradores múltiples:** la regla no autoriza `int a, b;` si se sigue
  {ref}`0x0002h`, aunque el espaciado sea correcto.
- **Macros con comas:** los argumentos de una macro funcional siguen la
  misma convención.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` / `gaff fix archivo.c` | Coma sin espacio posterior. |
| `grep` | `grep -nE ',[^[:space:]\n]' archivo.c` | Posibles comas pegadas. |
| `clang-format` | `clang-format --dry-run archivo.c` | Reespaciado de listas. |

## Checklist de autocontrol

- [ ] ¿Toda coma lleva exactamente un espacio después?
- [ ] ¿Ninguna coma lleva espacio antes?
- [ ] ¿Revisé tanto declaraciones como llamadas?
- [ ] ¿Evité pegar argumentos en listas largas?

## Reglas relacionadas

* {ref}`0x0019h` — sin espacio antes de `;` ni de `,`.
* {ref}`0x002Bh` — espaciado en listas de argumentos y llamadas.
* {ref}`0x001Dh` — sin espacios internos en paréntesis.
* {ref}`0x0004h` — espaciado alrededor de operadores binarios.
* {ref}`0x001Eh` — prohibición de espacios múltiples.
