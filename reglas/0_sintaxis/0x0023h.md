(0x0023h)=
# 0x0023h: Detector de variables locales no inicializadas con modificador const

:::{admonition} Categoría: Sintaxis Básica y Nomenclatura (0x00XX)
:class: note
Código de regla: `0x0023h` | Soporta corrección automática: **No**
:::

:::{seealso} Reglas relacionadas
* {ref}`0x0003h` — toda variable debe inicializarse a un valor conocido.
* {ref}`0x3017h` — el calificador `const` precede al tipo (`const int x`).
* {ref}`0x3018h` — los agregados se inicializan con `{0}`.
:::

## Enunciado normativo

> Toda variable declarada con el calificador `const` **DEBE** inicializarse en
> la misma sentencia de su declaración. **NO DEBE** declararse un objeto `const`
> sin valor.

## ¿Por qué existe esta regla?

### El problema

`const` significa que el objeto no puede modificarse después de su creación. En
C no hay constructores ni una lista de inicialización diferida: la única
oportunidad de darle un valor a un objeto `const` es su declarador. Si se
declara `const int limite;` sin inicializador, no queda ningún camino legal para
asignarle un valor: `limite = 10;` es un error de compilación porque el objeto
es de sólo lectura. El resultado es un objeto inmutable al que nunca se le dio
contenido; leerlo produce un valor indeterminado, y el estándar trata esa
lectura como comportamiento indefinido para objetos automáticos.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Compilación | `limite = 10;` produce `error: assignment of read-only variable 'limite'`. |
| Comportamiento indefinido | Leer el objeto `const` sin inicializar es leer un valor indeterminado. |
| Bug silencioso | `gcc` advierte sólo cuando detecta el uso; si no, el valor basura viaja hasta el resultado. |
| Mantenibilidad | El lector no puede saber cuál debía ser el valor original. |

### Fundamento en el estándar y en la cátedra

ISO/IEC 9899:2011 §6.7.9 (Initialization), §6.7.3 (Type qualifiers) y §6.2.4
(Storage durations) sustentan la regla: un objeto automático sin inicializador
explícito tiene valor indeterminado (§6.7.9p10), y un objeto `const` no admite
asignación posterior. La cátedra la exige porque un `const` vacío suele esconder
la intención de "declarar y luego calcular"; ese patrón se escribe con una
variable no `const` y, si se desea, una copia `const` al final del cálculo.

## Alcance y excepciones

Aplica a objetos locales y a los de duración estática de nivel de archivo. Los
de duración estática se inicializan a cero por el estándar (§6.7.9p10), pero la
cátedra pide el inicializador explícito por claridad. **No aplica** a parámetros
`const` (el inicializador es el argumento) ni a una declaración `extern const`
(es sólo una declaración, no una definición). En un miembro `const` de `struct`,
el valor se aporta en el inicializador del agregado.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — `const` usado como tamaño de arreglo

```c
const int limite;
int valores[limite];
```

Por qué falla: `limite` nunca recibe valor y se usa como dimensión. Además, el
arreglo resulta un VLA, prohibido por {ref}`0x5001h`; los dos defectos se
potencian.

### ❌ Contraejemplo 2 — `const` leído en una fórmula

```c
const double iva;
double total = base * (1.0 + iva);
```

Por qué falla: compila con advertencia, pero `iva` contiene basura de la pila.
El resultado es indefinido y no reproducible entre ejecuciones.

### ✅ Ejemplo conforme 1 — Escalar inicializado

```c
const int limite = 100;
int valores[100];
```

Por qué cumple: el valor queda fijado en la declaración y el arreglo tiene
tamaño constante en tiempo de compilación.

### ✅ Ejemplo conforme 2 — Varios niveles de `const`

```c
const double iva = 0.21;
const char * const mensaje = "ok";
```

Por qué cumple: en la segunda línea, tanto el puntero como el contenido apuntado
son inmutables y ambos quedan fijados al declarar; el orden de calificadores
sigue {ref}`0x3017h`.

### ⚠️ Casos límite

- **`static const int x;` de archivo:** el estándar lo inicializa a cero, pero
  se escribe `= 0` para no depender de esa regla.
- **`int * const p = &v;` (puntero constante):** debe inicializarse; en cambio
  `const int *p;` (puntero a `const`) sí puede declararse vacío porque el
  puntero es mutable.
- **Arreglo `const`:** `const int v[3] = {0};` inicializa el agregado, ver
  {ref}`0x3018h`.
- **Prototipos:** `void f(const int x)` no requiere inicializador; el parámetro
  se inicializa con el argumento.
- **No confundir** con {ref}`0x3017h`: ésa ordena los calificadores, ésta exige
  el valor.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Reporta un `const` local declarado sin inicializador. |
| `gcc` / `clang` | `gcc -Wall -Wextra -std=c11 -c archivo.c` | `warning: uninitialized const 'limite'` cuando el uso es visible. |
| Revisión manual | — | Declaraciones `const tipo nombre;` sin `= valor`. |

## Checklist de autocontrol

- [ ] Todo `const` que declaré tiene su `= valor` en la misma línea.
- [ ] Distingo un puntero constante (`int * const`) de un puntero a `const`
      (`const int *`).
- [ ] No usé un `const` vacío como tamaño de arreglo.
- [ ] Los agregados `const` usan su inicializador de llaves.
