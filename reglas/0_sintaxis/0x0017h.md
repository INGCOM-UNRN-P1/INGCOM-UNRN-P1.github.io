(0x0017h)=
# 0x0017h: Espaciado consistente en declaraciones de doble puntero (tipo **var)

:::{admonition} Categoría: Sintaxis Básica y Nomenclatura (0x00XX)
:class: note
Código de regla: `0x0017h` | Soporta corrección automática: **Sí**
:::

## Enunciado normativo

> **DEBE** escribirse los asteriscos de un doble puntero unidos entre sí y
> adheridos al identificador (`char **argv`). **NO DEBE** separarse los
> asteriscos entre sí ni del nombre (`char* *argv`, `char * * argv`,
> `char** argv`).

La regla extiende la convención de {ref}`0x0006h` a dos o más niveles de
indirección.

## ¿Por qué existe esta regla?

### El problema

Cada asterisco de una declaración de puntero forma parte del declarador
(§6.7.6). Separarlos con espacios (`char * * argv`) hace que el lector dude de
si son dos operadores distintos o parte de un mismo tipo. Pegarlos al tipo
(`char** argv`) vuelve a crear la ilusión de un tipo atómico y contradice la
convención de un solo puntero.

La forma canónica `char **argv` mantiene la coherencia: el tipo (`char`) y
luego los dos asteriscos pegados al nombre, que es lo que se desreferencia.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Compilación | Ninguna: todas las variantes son válidas. |
| Legibilidad | La cantidad de niveles de indirección se vuelve difícil de contar. |
| Bug silencioso | Se confunde `**` con dos operadores y se desreferencia de más. |
| Consistencia | Un archivo mezcla `char **`, `char* *` y `char **`. |
| Mantenibilidad | Cambiar el nivel de indirección exige reescribir el espaciado. |

### Fundamento en el estándar y en la cátedra

El estándar permite separar los tokens con cualquier cantidad de espacios
(§6.4). La cátedra fija `tipo **var` como la única forma correcta para que
los niveles de indirección se cuenten con la vista y para unificar la
convención con {ref}`0x0006h`.

## Alcance y excepciones

Aplica a variables, parámetros, campos, retornos y typedefs con dos o más
asteriscos. En punteros a función la forma canónica es
`tipo (*identificador)(params)` ({ref}`0x0025h`), donde el asterisco va unido
al nombre entre paréntesis. Las conversiones (`(char **)p`) siguen la misma
convención.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Asteriscos pegados al tipo

```c
int main(int argc, char** argv)
{
    return 0;
}
```

Por qué falla: `char**` parece un tipo atómico; contradice la forma
`char *` de un solo puntero y dificulta extenderlo a tres niveles.

### ❌ Contraejemplo 2 — Asteriscos separados entre sí

```c
char * * argv;
int * * matriz;
```

Por qué falla: los espacios entre asteriscos hacen que `* *` se lea como dos
operadores; el lector debe detenerse a contar cuántos niveles hay.

### ✅ Ejemplo conforme 1 — Doble puntero canónico

```c
int main(int argc, char **argv)
{
    return 0;
}
```

Justificación: el tipo queda separado y los dos asteriscos, unidos entre sí y
al nombre, se leen como un solo declarador de dos niveles.

### ✅ Ejemplo conforme 2 — Parámetro de salida

```c
static int crear_tabla(size_t filas, size_t columnas, int ***salida)
{
    *salida = NULL;
    return 0;
}
```

Justificación: incluso con tres niveles la forma `int ***salida` mantiene los
asteriscos juntos y el número de desreferencias necesarias se ve de un
vistazo.

### ⚠️ Casos límite

- **`const` intercalado:** `const char **` califica al dato apuntado; el
  `const` precede al tipo y no altera la regla de los asteriscos.
- **Puntero a función con doble asterisco:** se combina con
  {ref}`0x0025h`; el asterisco del puntero va unido al nombre.
- **`argv`:** es el caso más común en `main`; conviene usarlo como ejemplo
  de referencia.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` / `gaff fix archivo.c` | Asteriscos separados o pegados al tipo. |
| `grep` | `grep -nE '(\*\s+\*|\w+\*\*)' archivo.c` | Candidatos a espaciado incorrecto. |
| Revisión manual | — | Contar niveles de indirección con la vista. |

## Checklist de autocontrol

- [ ] ¿Los asteriscos del doble puntero están unidos entre sí?
- [ ] ¿Están adheridos al identificador?
- [ ] ¿Evité `char** argv` y `char * * argv`?
- [ ] ¿Apliqué la misma forma en parámetros y conversiones?
