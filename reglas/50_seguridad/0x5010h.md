(0x5010h)=
# 0x5010h: Prohibición de directivas #pragma no estándar o privativas

:::{admonition} Categoría: Compilacion, preprocesador y seguridad (0x50XX)
:class: note
Código de regla: `0x5010h` | Soporta corrección automática: **No**
:::

## Enunciado normativo

> **NO DEBEN** usarse directivas `#pragma` específicas de un compilador
> (`#pragma warning`, `#pragma comment` de MSVC) ni extensiones privativas. Las
> advertencias y opciones se configuran con banderas estándar (`-Wall`, ...).

## ¿Por qué existe esta regla?

### El problema

El estándar ISO C define `#pragma` como una vía de escape **para la
implementación**: su contenido es libre y cada compilador decide qué reconoce.
Un `#pragma` desconocido se ignora silenciosamente, de modo que el código
parece compilar pero la intención no se cumple. `#pragma warning(disable: 4996)`
silencia una advertencia en MSVC, pero en GCC no hace absolutamente nada; el
programa queda con el mismo defecto y la falsa sensación de estar «arreglado».

Peor aún, algunas directivas atan el código a una plataforma: `#pragma
comment(lib, "ws2_32")` pide una biblioteca por nombre, algo que sólo entiende
el enlazador de MSVC. El proyecto deja de compilar en Linux.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Portabilidad | La directiva se ignora o rompe en GCC/Clang. |
| Bug silencioso | El `#pragma` desconocido no avisa: la intención no se ejecuta. |
| Compilación | `unknown pragma` con `-Wunknown-pragmas` (incluida en `-Wall`). |
| Mantenibilidad | Oculta la verdadera configuración del proyecto en el código. |

### Fundamento en el estándar y en la cátedra

ISO/IEC 9899:2011 §6.10.6 define `#pragma`: «cada implementación puede reconocer
distintas directivas»; las no reconocidas se ignoran. La cátedra exige que la
configuración viva en el `Makefile` porque es ahí donde el corrector automático
la revisa, y porque el código debe compilar en GCC y Clang sin cambios.

## Alcance y excepciones

Aplica a todo `#pragma` privativo. **Excepción limitada:** las directivas
estandarizadas de control de diagnóstico de GCC/Clang (`#pragma GCC diagnostic
push/pop`) pueden usarse en el código propio para aislar una advertencia de una
biblioteca de terceros, documentando por qué. `#pragma once` no es ISO C: se
prefiere la guarda de inclusión ({ref}`0x5003h`).

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Silenciar una advertencia de MSVC

```c
#pragma warning(disable: 4996)

#include <stdio.h>

int main(void)
{
    char buf[16];
    gets(buf);
    return 0;
}
```

Por qué falla: en GCC la directiva se ignora (con `-Wall` avisa `unknown
pragma`), así que `gets` no queda habilitada de forma segura; además `gets` no
existe en C11. El `#pragma` sólo consigue que el código dependa de MSVC.

### ❌ Contraejemplo 2 — Enlazar una biblioteca con `#pragma comment`

```c
#pragma comment(lib, "ws2_32.lib")

#include <stdio.h>

int main(void)
{
    printf("hola\n");
    return 0;
}
```

Por qué falla: `#pragma comment` es una extensión de MSVC para el enlazador.
GCC no la reconoce y el enlace debe resolverse con `-lws2_32` en el `Makefile`;
la directiva no hace nada y confunde a quien lee el código.

### ✅ Ejemplo conforme 1 — Configuración con banderas

```make
CC     = gcc
CFLAGS = -std=c11 -Wall -Wextra -Werror -pedantic
app: main.c
	$(CC) $(CFLAGS) main.c -o app
```

Las advertencias y el nivel de exigencia quedan en `CFLAGS`, donde la cátedra
los revisa. El código fuente no contiene directivas dependientes del compilador.

### ✅ Ejemplo conforme 2 — Aislar una advertencia puntual de una dependencia

```c
#include "biblioteca_externa.h"

#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-parameter"
#include "encabezado_con_ruido.h"
#pragma GCC diagnostic pop
```

Cuando no queda otra que convivir con advertencias de una cabecera ajena, se
acota con `push`/`pop` alrededor del `#include`, se documenta la causa y no se
silencia el código propio. Es la única excepción admitida.

### ⚠️ Casos límite

- **`#pragma once`:** ampliamente soportado pero no estándar; si se usa, no
  reemplaza a la guarda y puede sorprender a otro compilador.
- **`#pragma pack`:** controla alineación y afecta el ABI; si se usa en una
  estructura persistida, hay que documentarlo y verificar plataformas.
- **`_Pragma`:** es la forma estándar de `#pragma` dentro de una macro, pero
  sigue dependiendo de que la implementación reconozca el contenido.
- **`-Wunknown-pragmas`:** incluida en `-Wall`; con `-Werror` la directiva
  privativa detiene la compilación en GCC.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | Reporta `0x5010h` ante `#pragma` no estándar. |
| `gcc` / `clang` | `gcc -std=c11 -Wall -Wextra -Werror -pedantic archivo.c` | `warning: ignoring '#pragma warning'` / `unknown pragma`. |

## Checklist de autocontrol

- [ ] ¿Evité `#pragma warning`, `#pragma comment` y similares?
- [ ] ¿La configuración de advertencias está en `CFLAGS`, no en el código?
- [ ] Si usé `#pragma GCC diagnostic`, ¿está acotado con `push`/`pop` y justificado?
- [ ] ¿El código compila en GCC y Clang sin directivas privativas?
