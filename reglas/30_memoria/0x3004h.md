(0x3004h)=
# 0x3004h: Utilizá typedef para definir tipos de estructuras con el sufijo _t

:::{admonition} Categoría: Memoria, punteros y tipos (0x30XX)
:class: note
Código de regla: `0x3004h` | Soporta corrección automática: **No**

:::
<!-- {admonition} Categoría: Memoria, punteros y tipos (0x30XX) -->

## Enunciado normativo

> **DEBE** declararse un alias con `typedef` para cada `struct`, `enum` o
  `union`
> que se use como tipo, y el alias **DEBE** terminar en el sufijo `_t`
> (`nodo_t`, `lista_t`, `estado_t`). El alias **DEBE** escribirse en
> `snake_case` minúsculo.

## ¿Por qué existe esta regla?

### El problema

En C, la etiqueta de un `struct` y un nombre de tipo viven en espacios de
nombres
distintos. Declarar `struct nodo { int dato; };` no crea un tipo llamado `nodo`:
obliga a escribir `struct nodo` cada vez, ensucia las firmas y abre la puerta a
olvidar la palabra clave. El `typedef` crea un alias en el espacio de nombres de
tipos, y el sufijo `_t` señala de un vistazo que se trata de un tipo.

### Consecuencias de violarla

| Tipo de consecuencia | Efecto concreto |
| :--- | :--- |
| Ruido sintáctico | Cada uso repite `struct`, sobre todo en punteros y arreglos. |
| Ambigüedad visual | `nodo` puede parecer una variable compartida en el código. |
| Inconsistencia | Conviven `Nodo`, `nodo`, `struct nodo` para el mismo concepto. |

### Fundamento en el estándar y en la cátedra

C11 §6.7.8 define `typedef` como declaración de un alias de tipo. La cátedra
adopta el sufijo `_t` como convención institucional, tanto para tipos públicos
como internos. La biblioteca reserva algunos nombres con ese sufijo (`size_t`,
`time_t`), pero el espacio del usuario es distinto.

## Alcance y excepciones

Aplica a `struct`, `enum` y `union` usados como tipo, incluidos los tipos
opacos. **No** aplica a alias de tipos básicos que oscurecen el significado
(`typedef int boom_t;`); la cátedra desaconseja esos alias. Tampoco exige
`typedef` en etiquetas que nunca se usan como tipo, aunque en la práctica toda
etiqueta termina siéndolo.

## Ejemplos exhaustivos

### ❌ Contraejemplo 1 — Alias en PascalCase

```{code-block} c
:linenos:
typedef struct nodo Nodo;
struct nodo
{
    int dato;
    Nodo *sig;
};

```
<!-- {code-block} c -->

Por qué falla: `Nodo` no respeta ni el `snake_case` de identificadores
({ref}`0x0102h`) ni el sufijo `_t`. El lector no distingue a simple vista un
tipo de una función, y el estilo se desvía del resto del catálogo.

### ❌ Contraejemplo 2 — Uso directo de `struct` sin alias

```{code-block} c
:linenos:
struct nodo
{
    int dato;
    struct nodo *sig;
};
void agregar(struct nodo *cabeza, int valor);
struct nodo *buscar(struct nodo *cabeza, int valor);

```
<!-- {code-block} c -->

Por qué falla: la interfaz repite `struct nodo` en cada firma. Es fácil omitir
la
palabra `struct` y obtener un error de tipo indefinido, y el código se vuelve
verboso justo donde la firma debería comunicar la intención.

### ✅ Ejemplo conforme 1 — Alias con sufijo `_t`

```{code-block} c
:linenos:
typedef struct nodo nodo_t;
typedef enum estado estado_t;
struct nodo
{
    int dato;
    nodo_t *sig;
};
enum estado
{
    ESTADO_NUEVO,
    ESTADO_LISTO,
    ESTADO_ERROR
};

```
<!-- {code-block} c -->

La forma `typedef struct nodo nodo_t;` separa la etiqueta del nombre de tipo y
permite que el `struct` se complete después, técnica base de los punteros
opacos de {ref}`0x301Dh`.

### ✅ Ejemplo conforme 2 — Tipo opaco con alias

```{code-block} c
:linenos:
/* lista.h */
typedef struct lista_t lista_t;
lista_t *lista_crear(void);
void lista_destruir(lista_t **lista);
/* lista.c */
struct lista_t
{
    nodo_t *cabeza;
    size_t cantidad;
};

```
<!-- {code-block} c -->

El alias `lista_t` aparece en la cabecera sin representación; el `struct` se
define en el `.c`. Así el cliente usa un único nombre corto y la implementación
queda libre de cambiar sus campos.

### ⚠️ Casos límite

- **Tipos internos:** el sufijo `_t` también aplica a los `typedef` privados del
  `.c`; la convención no depende de la visibilidad.
- **`struct` anónimo:** `typedef struct { int x; } punto_t;` es válido, pero
  impide referenciar la etiqueta; usalo sólo si nunca la necesitás.

## Cómo detectarla

| Herramienta | Comando | Señal |
| :--- | :--- | :--- |
| `gaff` | `gaff check archivo.c` | `typedef` cuyo alias no termina en `_t` o no está en `snake_case`. |
| `gcc` / `clang` | `gcc -Wall -Wextra -std=c11 ...` | No detecta la convención de nombres. |
| Revisión manual | — | Firmas con `struct x` repetido en lugar de un alias. |

## Checklist de autocontrol

- [ ] ¿Definí un alias `typedef` para cada `struct`/`enum`/`union`?
- [ ] ¿El alias termina en `_t`?
- [ ] ¿El alias está en `snake_case` minúsculo?
- [ ] ¿Usé el alias en todas las firmas en lugar de `struct x`?
- [ ] ¿Evité reutilizar nombres reservados por la biblioteca estándar?

## Reglas relacionadas
