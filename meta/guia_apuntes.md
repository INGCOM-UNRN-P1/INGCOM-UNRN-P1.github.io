# Guía editorial para apuntes

Los apuntes enseñan un concepto. No son inventarios exhaustivos ni manuales de
referencia: deben conducir desde un modelo inicial hasta una práctica observable.

## Apertura obligatoria

Antes de la explicación extensa incluir:

1. prerrequisitos concretos;
2. dos o tres objetivos observables;
3. una comprobación de salida;
4. un ejemplo mínimo compilable, ejecutable o trazable.

La primera actividad debe usar solo conocimientos ya declarados. Evitar comenzar
con historia, taxonomías o detalles de ABI antes de que el lector haya hecho una
acción.

## Secuencia de cada concepto

Usar el ciclo: problema → modelo → ejemplo → microactividad → límite o error →
aplicación. Definir cada término antes de reutilizarlo y separar el camino
obligatorio de las lecturas avanzadas (`A`, `B`, `C`, …). Un apunte posterior
puede aplicar un contrato anterior, pero no redefinirlo con otra terminología.

## Código y explicaciones

Cada bloque debe indicar lenguaje, dependencias y comando de compilación cuando
corresponda. Los ejemplos inseguros deben estar marcados como deliberados y
aislados. Después del código explicar qué se observa, por qué ocurre y qué
precondición lo hace válido; no describir únicamente la sintaxis.

## Cierre

Cerrar con un resumen de decisiones, una actividad integradora y enlaces a la
continuación. Las referencias bibliográficas y lecturas complementarias van al
final, no antes del primer ejemplo.
